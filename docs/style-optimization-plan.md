# MidiDraft 三套样式与排版优化计划

日期：2026-09-23  
状态：待实施，供后续 agent 执行。

本次交付仅为计划文档，不包含代码改动、Git 初始化、分支创建或部署。

## 1. 目标与范围

围绕 MidiDraft 的核心流程，分别实现三个可独立预览的视觉版本：

> 选择本地音频 → 选择片段 → 转换 → 原音 / MIDI 对比试听 → 清理与量化 → 导出 MIDI

三个版本保留相同功能、产品事实和示例素材，允许排版、信息密度、组件形态与操作区域的组织方式不同。比较真实操作体验，而不只是首页配色。

目标用户是音乐制作人、旋律创作者及需要音频转 MIDI 的用户。现有 `docs/design.md` 仍包含 SaaS 模板的开发者定位；本次设计实验以本计划、当前 `AGENTS.md` 和 `src/config/product.ts` 的产品定位为准。各分支实施时同步更新自己的设计说明。

实施范围：

- 首页导航、标题区、转换器、试听示例、说明内容、FAQ 和页脚。
- 转换器各状态下的排版与控件视觉，包括波形、钢琴卷帘、播放控制和参数面板。
- 桌面及移动端适配、键盘操作、焦点和反馈状态。
- 与首页直接相连的已上线示例页面保持视觉一致。
- 登录等共享组件检查样式回归；后台、支付及其他业务页面不做全面重设计。

## 2. 三个独立分支：必须从同一基线开始

| 版本 | 建议分支名 | 设计方向 |
| --- | --- | --- |
| A | `design/linear-workbench` | 专业暗色工作台 |
| B | `design/teenage-instrument` | 桌面音乐仪器 |
| C | `design/elevenlabs-studio` | 亲和的暖白音频工具 |

执行要求：

1. 实施 agent 先检查 Git 状态、当前代码和最新仓库指引。编写本计划时，当前目录没有 `.git`，因此不能假定分支已经存在。
2. 若执行时仍非 Git 仓库，先确认正式仓库位置；若要在当前目录建立仓库，按当时授权处理。建立首个提交前核对忽略规则，避免纳入 `.env`、依赖、构建产物及本地运行数据。
3. 保存需要保留的现有工作，确定一个包含本计划的共同基线提交，记录完整 commit SHA。
4. **三个分支都从该基线分别创建，不能从已完成的 A 分支派生 B 或 C。** 不覆盖用户未提交的改动，不重置已有同名分支。
5. 多个 agent 同时执行时，每个分支使用独立 worktree；不能在同一个工作目录里反复切换分支并同时编辑。顺序执行也必须保持三个分支独立。
6. 每个分支独立完成样式、布局、验证和截图。不要将三套样式混入一个全局 CSS，也不需要在产品中增加 A/B/C 风格选择器。
7. 如发现所有版本都需要的功能修复，单独记录并统一同步到三个分支，保持比较基准一致。
8. 完成后提供分支、提交、启动方式、截图和已知问题，交由用户比较。选定方案前不合并三套方案，不自动部署。

## 3. 共同产品约束

- 首页就是工具，首屏必须能选择文件或试用示例，不增加独立的 `/audio-to-midi` 页面。
- 音频处理完全在浏览器内完成。界面可表达拖入或选择文件，但不能暗示音频上传服务器。
- 保留免费完成转换和导出的流程，不新增登录或付费门槛。
- 文件大小、时长、片段长度、格式支持以现有实现和配置为准，不由设计稿另行承诺。
- 保留清晰的能力限制和效果不佳的示例，不添加未经验证的准确率。
- 保留现有 feature flags，不展示尚未上线的批量处理、MIDI 导入或付费功能。
- 本次“编辑”指现有清理、检测参数、量化和相关调整；不借视觉改版扩展为完整的音符拖拽编辑器。
- 保持推理与音符提取分离；调整阈值不重复运行完整模型。保留模型动态加载，不增加入口包负担。
- 保留 A/B 试听共享播放位置、导出节奏信息和现有错误恢复能力。

## 4. 三套方案共享的排版优化

### 4.1 首页信息顺序

1. 精简导航：品牌、必要的已上线入口、主题切换等已有功能。
2. 简短标题与一句说明，紧接可操作的转换器。
3. 试听示例：让用户快速判断什么素材适合转换。
4. 合并后的操作说明与使用场景，避免重复介绍同一流程。
5. 精简的格式、隐私和能力限制说明。
6. FAQ 与页脚。

格式、免费导出和本地处理等关键信息也应出现在文件选择区域附近。首屏不被大型装饰图、品牌动画或重复文案占满。

### 4.2 随操作状态分配空间

| 状态 | 内容与操作重点 |
| --- | --- |
| 未选择文件 | 文件选择 / 拖入区、试用示例、格式与限制提示 |
| 解码及片段选择 | 文件信息、波形、现有片段选择控件、开始转换 |
| 转换中 | 真实处理阶段与进度、已有取消能力、明确的禁用状态 |
| 转换完成 | 原音 / MIDI 试听、音符预览、导出；文件选择区收成紧凑信息栏 |
| 调整展开 | 清理、量化、检测参数与节奏信息；保留试听入口 |
| 空结果或错误 | 可理解的原因、可执行的恢复方式、重新选择或调整入口 |

转换前突出输入，转换后把主要空间交给试听与音符。布局变化不能重置文件、参数或播放器，也不能在没有用户操作时抢走键盘焦点。

### 4.3 响应式与可用性

- 桌面可采用分栏；窄屏按任务顺序单列显示，禁止整页横向溢出。
- 钢琴卷帘需要横向滚动时，仅在其内部滚动。
- 手机端播放与导出应易于触达；采用吸底控件时预留安全区和正文空间，避免遮挡。
- 重要按钮有文字标签；进度、模式和错误不能仅用颜色区分。
- 交互目标建议至少 44px，正文保持易读字重和对比度，焦点清晰可见。
- 动效用于反馈，支持减少动态效果偏好，不做持续装饰性闪烁。
- 保留现有主题切换能力。A 以暗色作为默认体验，B/C 以浅色作为默认体验；另一主题也必须可用。比较截图时显式选择主题，避免浏览器已保存设置影响结果。

## 5. 方案 A：Linear — 专业暗色工作台

参考：[Refero / Linear](https://styles.refero.design/style/90ce5883-bb24-4466-93f7-801cd617b0d1)

设计目标：精简音乐制作软件的工作台，突出专注感与操作效率。以下色值是 MidiDraft 的方案建议，不要求复制参考站的全部规范。

### 视觉规范

- 近黑画布 `#08090A`，深灰面板 `#141618`，边框 `#292C31`，灰白正文。
- 主强调色 `#DDF244`，用于主要操作、选中音符和播放位置，避免大面积铺色。
- Inter 为主字体，时间、BPM 和参数读数使用等宽字体。
- 面板圆角 12px，按钮圆角 6px；以背景层次和细边框组织界面。
- 低对比网格配清晰音符，正文和辅助标签不能因追求暗色氛围而难以阅读。

### 桌面布局

未选择文件时：左侧为短标题与说明，右侧为上传/文件选择卡片。完成选择后，标题收紧，工作区扩展至内容全宽。

```text
文件名 / 片段信息                                  更换文件
原音波形与片段选择
────────────────────────────────────────────────────────
钢琴卷帘与音符预览（主区域）       │ 清理 / 量化 / 检测参数
                                  │ BPM 与结果摘要
────────────────────────────────────────────────────────
播放 / 原音·MIDI / 循环 / 时间                         导出
```

- 参数栏只在有意义的状态出现，未转换时不展示一整列不可用设置。
- 播放区域固定在工作区底部，不随参数展开而跳动。
- 示例使用紧凑音轨列表，其余说明采用细分隔线和克制的卡片结构。
- 手机端参数区折叠到主预览下方，保留清晰的试听与导出操作。

验收重点：结果区信息密度合理；主要操作一眼可见；暗色细节仍可读；初始状态没有复杂软件的压迫感。

## 6. 方案 B：teenage engineering — 桌面音乐仪器

参考：[Refero / teenage engineering](https://styles.refero.design/style/aecf9dda-5cba-4dc7-9e73-59b65d895cdf)

设计目标：有品牌辨识度的小型音乐设备，强调清晰的结构、参数和操作节奏。

### 视觉规范

- 灰白背景 `#F6F8F7`，浅灰设备面板 `#E9EBE8`，近黑文字 `#151515`。
- 增加少量信号橙 `#F26522`，用于功能性强调。这是 MidiDraft 的设计调整，不是对参考站配色的照搬。
- 无衬线标题，参数和区域编号采用等宽字体；正文不照搬超细字重。
- 直角或 2px 微圆角，明确分隔线、平整表面，避免强阴影和拟物装饰堆积。
- 编号仅辅助组织信息，必须同时保留可读的区域名称。

### 桌面布局

左对齐标题，上方小型品牌/用途标识，下方是一整块设备面板。

```text
01 INPUT                  02 TRANSCRIBE             03 OUTPUT
───────────────────────────────────────────────────────────
输入文件 / 波形 / 片段选择         │ MIDI 音符预览
───────────────────────────────────────────────────────────
播放 / 停止        ORIGINAL / MIDI        循环 / 时间
───────────────────────────────────────────────────────────
量化 [选项]        清理 [选项]        BPM [数值]       [导出]
```

- 三个编号表达流程，不新增强制逐步跳页。
- 未选择文件时强调输入区；结果生成后输入与输出并列展示；展开调整时音符区可扩展至全宽。
- 采用分段按钮、带刻度滑杆和清晰读数，不制作难操作的旋钮。
- 状态指示点同时带文字，不能仅靠灯的颜色判断是否完成。
- 示例使用标注乐器、时长和试听入口的素材样本卡，说明区延续编号与网格。
- 手机端输入与输出纵向排列，参数分组换行，不挤成一排小控件。

验收重点：具备音乐设备感且操作直观；标签可读；橙色使用克制；功能不依赖难理解的缩写或拟物交互。

## 7. 方案 C：ElevenLabs — 暖白音频创作工具

参考：[Refero / ElevenLabs](https://styles.refero.design/style/031056ff-7af1-46db-8daa-115f731c5d26)

设计目标：降低第一次使用的理解成本，让用户轻松完成转换、试听与导出。

### 视觉规范

- 暖白背景 `#FDFCFC`，米灰卡片 `#F5F3F1`，深色正文与黑色主按钮。
- 蓝色和橙色主要用于原音与 MIDI 可视化，不把所有按钮做成彩色。
- Inter；标题可用轻字重，正文常规字重，适当放宽行距。
- 卡片圆角 20–24px，胶囊操作按钮，细边框和宽松间距。
- 音频可视化作为主视觉，避免装饰球体挤占工具首屏。

### 桌面布局

居中短标题，下方大文件选择卡片，示例入口紧随其后。结果采用单列渐进展开。

```text
文件信息                                           更换
原音波形与片段信息
──────────────────────────────────────────────────────
原音 / MIDI 切换与播放
MIDI 音符预览
结果摘要
[调整音符]                                  [下载 MIDI]
（展开后显示清理、量化、检测参数和 BPM）
```

- 默认突出试听与下载，次级参数在用户需要时展开。
- A/B 模式共享时间刻度和播放位置，不产生两个互相独立的播放器。
- 桌面示例采用三张卡片，直接提供转换前后试听；移动端纵向展示。
- 操作说明与 FAQ 保持易读，但转换结果区域不能因留白过多而要求反复滚动。
- 展开参数后保留试听与导出入口，不把主操作推到很远的位置。

验收重点：首次使用路径清楚；结果无需长距离滚动即可试听和下载；展开设置后依然具有足够的编辑空间。

## 8. 实施文件与步骤

实施前复查文件实际内容，以下为当前主要入口：

| 区域 | 文件或目录 |
| --- | --- |
| 首页组合与内容 | `src/components/home/` |
| 转换器状态与布局 | `src/components/converter/converter.tsx` |
| 文件选择 | `src/components/converter/drop-zone.tsx` |
| 音频与音符预览 | `src/components/converter/waveform.tsx`、`piano-roll.tsx` |
| 播放与参数 | `src/components/converter/transport.tsx`、`settings-panel.tsx` |
| 导航、页脚及容器 | `src/components/layout/` |
| 样式与主题 | `src/styles.css`、`src/custom.css`、`src/config/website.ts` |
| 首页路由与元数据 | `src/routes/index.tsx` |
| 产品约束与音频逻辑 | `src/config/product.ts`、`src/lib/midi/` |

每个分支按以下顺序执行：

1. 阅读仓库指引与本计划，记录共同基线和原有验证问题，确认真实功能边界。
2. 建立该方案的颜色、字体、间距、圆角和主题变量。
3. 调整首页层级与未选择文件状态，确保首屏直接操作。
4. 完成片段选择、转换进度、结果、参数展开、错误及空结果布局。
5. 统一导航、示例、说明、FAQ、页脚及已上线示例页的视觉。
6. 完成移动端、键盘和另一主题的适配。
7. 运行验证，记录实际结果并提供可复现的预览方式。

尽量保留现有状态管理和处理逻辑，只调整组件组合与呈现。避免因响应式条件渲染重新挂载转换器而丢失音频状态。不要手动编辑 `src/routeTree.gen.ts`，也不要为了三套视觉增加新的公开 SEO 路由。

## 9. 验证与对比标准

### 功能回归

- 本地文件和现有示例均可使用，限制提示与实际行为一致。
- 片段选择、转换、A/B 试听、循环、清理、量化及导出保持可用。
- 调整参数不丢失音频或错误重跑完整推理。
- 更换文件、取消、错误和空结果均有可恢复路径。
- 导出的 MIDI 可由现有读取能力或音乐软件打开，并保留预期音符及节奏信息。
- 无新增控制台错误、水合错误或明显布局跳动。

### 工程验证

- 每个分支运行 `pnpm check` 和 `pnpm build`，区分基线问题与新增问题，不能把未执行或失败的检查写成通过。
- 使用 `pnpm dev` 完成实际浏览器验证，记录必要的环境阻塞。
- 不为纯样式变化新增镜像式测试；若确实改动交互逻辑，补充与风险相称的验证。

### 统一截图与体验对比

三个版本使用相同素材、参数、浏览器缩放和视口，建议桌面 1440×900、移动端 390×844，并额外检查 320px 窄屏及 200% 缩放。

每个版本至少记录：

1. 首页初始状态及完整页面。
2. 已选择音频、可选择片段状态。
3. 实际转换中状态。
4. 转换完成、可以试听与导出状态。
5. 参数展开状态。
6. 错误或空结果状态。

截图命名包含方案、状态、视口和主题；动画或推理较快时可用录屏记录真实过程，不用假进度代替功能验证。移动端重点记录初始、结果和参数展开状态。

| 比较维度 | 判断问题 |
| --- | --- |
| 首次使用 | 能否快速理解并开始选择文件或试听示例？ |
| 操作效率 | A/B 切换、调整与导出是否容易找到？ |
| 音乐属性 | 波形、音符、时间与参数是否构成清晰的产品特征？ |
| 信息层级 | 主操作、次级参数和说明是否主次分明？ |
| 品牌辨识度 | 是否有记忆点且不影响使用？ |
| 移动端 | 是否易读、易操作且没有遮挡与整页溢出？ |

## 10. 每个实施 agent 的交付清单

- 对应的独立分支名、共同基线 SHA 和最终提交 SHA。
- 完整可运行的方案，附本地预览命令和实际使用的端口/地址。
- 桌面及移动端截图或必要录屏，注明素材、状态与主题。
- 检查、构建和手动回归结果，包括失败项及原因。
- 简短说明关键布局选择、相对参考站的调整及已知限制。
- 结果说明建议保存在各自分支的 `docs/style-review.md`，截图使用项目约定的附件位置并提供链接。

建议完成顺序为 A → B → C；也可在独立 worktree 中分别实施。A 用来验证专业工作台体验，B 探索音乐品牌辨识度，C 验证低门槛使用体验。最终取舍由三个可运行版本的实际比较决定。
